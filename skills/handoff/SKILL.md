# handoff

Fill HANDOFF.md with objective, actual commit/worktree/dirty state, changed files, executed checks, artifact paths and active job IDs. Record unresolved failures, next actionable command and conditions for ownership transfer. Do not start competing writes while another worker owns the component. Keep the handoff short and link existing evidence instead of duplicating reports.

Before final handoff, apply the learn skill: record durable lessons in the repository and shared KB, and link generalizable upstream agent-rules changes or a documented blocker. State explicitly if no durable lesson was found.

Include recurring workflow records, skill candidate disposition and committed new/extended skill paths (or an exact blocker). Do not count repeated commands within the same task as independent uses.
