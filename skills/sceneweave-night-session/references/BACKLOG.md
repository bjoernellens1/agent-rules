# Six-wave backlog template

Refresh this table from actual local/remote state. These are allowed candidate cards, not mandatory reruns or permission to alter frozen results. Complete prerequisite audits before dependent screens. Each card gets its own pre-registered mechanism, incumbent, estimate, primary metric and kill criterion. Stop/park failed branches; follow independent fallbacks. Reuse valid existing outputs. Default five lanes, six waves (~30 cards) plus coordinator verification; maximum 36 cards / 24 new paired development screens, subject to actual budgets and repository-specific limits.
